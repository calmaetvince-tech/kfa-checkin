# KFA — Kallistis Fight Academy QR Check-in PWA

Mobile-first web app for Kallistis Fight Academy (Muay Thai). The owner adds
members and scans their QR codes from a phone. Members get a personal link with
their QR code and their own check-in stats.

**Brand assets:** the logo lives at `public/brand/kfa-logo.png` (light-on-dark)
and `public/brand/kfa-logo-light-bg.png` (dark-on-light). Home-screen icons are
generated into `public/icons/`.

- **Stack:** Next.js 14 (App Router) + Tailwind + Supabase (Postgres + Auth)
- **Camera scan:** `html5-qrcode` (in-browser, no native install)
- **PWA:** manifest + maskable icons, designed to be added to home screen
- **Deploy target:** Vercel

## What's in the box

| Route | Who | What it does |
|---|---|---|
| `/` | Public | Landing page |
| `/login` | Owner | Email/password sign-in |
| `/dashboard` | Owner | Member list, monthly visits, subscription status |
| `/dashboard/add` | Owner | Create a new member (with optional starting subscription) |
| `/dashboard/member/[id]` | Owner | Member detail, QR code, renew subscription, delete |
| `/dashboard/scan` | Owner | Camera-based QR scan that logs a check-in instantly |
| `/m/[token]` | Member | Personal QR code + my stats (no login needed — token = secret) |

## Setup

### 1. Install dependencies

```bash
npm install
```

### 2. Create a Supabase project

1. Create a project at <https://supabase.com>.
2. From **Project Settings → API**, copy:
   - `Project URL` → `NEXT_PUBLIC_SUPABASE_URL`
   - `anon` public key → `NEXT_PUBLIC_SUPABASE_ANON_KEY`
   - `service_role` secret key → `SUPABASE_SERVICE_ROLE_KEY` (server-only!)

### 3. Configure environment

```bash
cp .env.example .env.local
# then fill in the values
```

### 4. Apply the schema

Two ways:

**Option A — Supabase MCP / SQL editor:** open `supabase/migrations/0001_init.sql`
in the SQL editor and run it.

**Option B — Supabase CLI:**

```bash
supabase link --project-ref <your-ref>
supabase db push
```

### 5. Create the owner account

In Supabase **Authentication → Users**, click **Add user** → set email/password.

Then grant admin: in the SQL editor run

```sql
insert into public.admins (user_id)
select id from auth.users where email = 'owner@yourgym.com';
```

(There's a template at `supabase/migrations/0002_seed_admin.sql.example`.)

### 6. Run locally

```bash
npm run dev
```

Open <http://localhost:3000>. Sign in at `/login`, then add a member.

> **Camera note:** browsers only grant camera access over HTTPS or `localhost`.
> If you test the scan page on your phone over LAN, use a tunnel (ngrok, cloudflared)
> or deploy to Vercel first.

## Deploy to Vercel

1. Push this folder to a Git repo.
2. Import into Vercel.
3. Add the four env vars (same as `.env.local`) — set
   `NEXT_PUBLIC_APP_URL` to your production URL so member QR codes encode the
   right host.
4. Deploy.

Once live, install it as a PWA on your phone: open in Safari/Chrome →
**Share → Add to Home Screen**.

## Data model

```
admins        (user_id PK → auth.users)
members       (id, name, email, phone, qr_token UNIQUE,
               subscription_renewed_at, subscription_expires_at, notes, created_at)
check_ins     (id, member_id FK, checked_in_at)
```

- `qr_token` is a 32-char random hex string generated by Postgres
  (`encode(gen_random_bytes(16), 'hex')`). It's the secret embedded in the QR.
- Subscription is just two timestamps; "active" is derived
  (`subscription_expires_at > now()`).

### Row-level security

- `members` + `check_ins`: only callable by users in `admins`.
- The public member page (`/m/[token]`) reads via the **service-role key on the
  server**, scoped to the token in the URL. The service-role key never leaves
  the server.

## How the QR flow works

1. Owner adds a member. The DB generates `qr_token`.
2. Owner shares `https://yourapp/m/<token>` with the member (visible on the
   member-detail page).
3. The member opens it → sees their QR (the same URL encoded) + their stats →
   "Add to Home Screen".
4. At the gym, the member shows the QR. Owner opens `/dashboard/scan` →
   camera → the URL is decoded → server action looks up `qr_token`, inserts a
   `check_ins` row, returns the member's status.

## Customization knobs

- Subscription length: default = 1 month, configurable per add/renew action.
- Token format: anything matching `/^[A-Za-z0-9_-]{8,}$/` in
  [`actions.ts`](app/dashboard/scan/actions.ts).
- Brand color: `tailwind.config.ts` (`brand`).
